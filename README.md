# LITHOS — инженерные загадки древности

Интерактивный атлас десяти сооружений: от каменных комплексов неолита до Пума-Пунку в мире Тиуанако первого тысячелетия нашей эры.

**Приложение:** https://evgk724.github.io/lithos-atlas/

## Коллекция

Пирамида Хеопса, Осирион, Серапеум Саккары, Баальбек, Гёбекли-Тепе, Стоунхендж, Ньюгрейндж, Хаджар-Ким, Пума-Пунку и Аль-Хазне в Петре.

Это авторская подборка инженерно сложных памятников, а не объективный рейтинг «необъяснимости». Для каждого объекта отделены археологические свидетельства, инженерные объяснения и открытые вопросы. Даты относятся к определённым строительным фазам. Материалы и ссылки на музеи, археологические организации и научные работы сохранены в `sources.json` и встроены в приложение.

## Возможности

- 20 оригинальных SVG-схем: общий вид и устройство каждого объекта; подписи также показаны крупным HTML-текстом.
- Карта по географическим координатам с отдельной врезкой Анд и упорядоченная хронология.
- Поиск по названиям и местам, фильтры коллекции, прямые ссылки на объект и режим.
- 50 карточек для активного воспроизведения: название, география, эпоха, инженерная идея, факты и гипотезы.
- Ответ скрыт до нажатия. «Повторить» назначает возврат через 10 минут; «Вспомнил» увеличивает интервал по цепочке 1, 3, 7, 14 и 30 дней; «Легко» перескакивает на следующий интервал. Новая карточка с «Легко» назначается через 3 дня. Обязательного количества повторений и оценок нет.
- Три размера текста: крупный, очень крупный и максимальный. Размер и реальная история повторений сохраняются в `localStorage` этого браузера; межустройственной синхронизации нет.
- Оригинальная иконка для домашнего экрана, favicon, web manifest, встроенный QR-код.
- `docs/LITHOS.html` — автономный HTML со встроенными кодом, схемами, иконкой и QR. Для перехода по внешним источникам нужен интернет.

## Сборка

Сторонние зависимости для сборки не требуются. Нужен Python 3.

```sh
python3 scripts/build.py
python3 -m http.server 8768 --directory docs --bind 127.0.0.1
```

Открыть `http://127.0.0.1:8768/`. GitHub Pages публикует папку `docs` ветки `main`.

Проверка планировщика повторений, записей коллекции и карточек:

```sh
node tests/learning.cjs
```

Исходники находятся в `src`, сборка — в `docs`. Приложение не требует внешних JS-библиотек, CDN, серверной базы или регистрации. Service worker не используется: для гарантированного автономного чтения скачайте HTML в разделе «Об атласе».

## Изображения и точность

Схемы созданы в SVG для этого приложения. Они поясняют конструктивные принципы и не являются масштабными археологическими обмерами. Утраченные детали реконструированы условно; гипотезы о строительных операциях не выдаются за зафиксированную историю каждой операции.

Оригинальная иконка создана встроенным инструментом `image_gen`. Ссылки на источники открываются отдельно; изображения из источников не копировались.

Проверка интерфейса: Chromium и WebKit, ширины 320, 430, 440, 834 и 1194 px, все три размера текста; поиск, фильтры, оба вида схем, хронология, карта, раскрытие ответов, интервалы и сохранение прогресса. Это браузерная проверка адаптивности, а не испытание на физических устройствах.


## Автообновление и крупный текст

- Онлайн-версия по умолчанию проверяет `version.json` при открытии, возвращении на страницу, восстановлении соединения и раз в минуту, пока страница видима. В фоне iOS может приостанавливать вкладку; проверка возобновляется при возвращении.
- В «Об атласе → Обновления приложения» есть переключатель автообновления, ручная проверка и кнопка установки найденной версии.
- Автоматическое применение ждёт завершения активного повторения, закрытия диалогов/полноэкранного чертежа и паузы в действиях. «Позже» откладывает обновление на пять минут. При ошибке сохранения прогресса автоматическое и ручное применение блокируются, чтобы не потерять текущие результаты.
- Перед переходом проверяется HTML конкретной новой версии по тому же URL. Неполная публикация или ошибка сети не вызывают переход. Неудачная установка одной версии не запускает бесконечную перезагрузку.
- Сохраняются прежние ключи истории и настроек. Выбранные объект/вид, фильтры, размер текста и положение чтения передаются новой странице. Приложения используют отдельные ключи хранения на общем домене GitHub Pages.
- Автообновление относится к опубликованным версиям приложения. Сохранённый файл `file://` остаётся автономной копией; в нём есть ссылка на онлайн-версию.
- Три размера основного текста: 22,5 / 24,75 / 27 CSS px. По умолчанию выбран средний; сохранённый выбор пользователя имеет приоритет. Насыщенность основного текста увеличена до 600, заголовков и большинства элементов управления — до 700–750.

Уже открытая старая версия без модуля обновлений требует однократного обычного обновления страницы. Последующие опубликованные версии будут обнаруживаться автоматически. Ссылки приложения и QR-коды не изменились.

Сборка `python3 scripts/build.py` сама формирует идентификатор из содержимого страницы и ресурсов и записывает `version.json`; вручную менять номер версии не требуется. В коммит нужно включать всю обновлённую сборку вместе с манифестом версии.

Браузерные регрессионные тесты обновления (требуется установленный Playwright с браузерами):

```sh
node tests/updater.cjs webkit
node tests/updater.cjs chromium
```

Проверяемые сценарии: новая версия, сохранение прогресса и настроек, активная карточка, отключение обновлений, ручная установка, сетевой сбой, частично опубликованная версия, запрет хранения, несохранённый прогресс, устаревший корневой URL, защита от цикла перезагрузок и «Позже» во время медленной загрузки.


Проверка этого обновления: WebKit — 84 сочетания приложения, размера экрана и шрифта; Chromium — ещё 36. Профили: 440×956 и 956×440 (iPhone 18 Pro Max), 820×1180 и 1180×820 (iPad Air 11″), 1024×1366 и 1366×1024 (iPad Air 13″), а также узкий экран 320×740. Во всех четырёх приложениях дополнительно проверены все объекты и все ответы при максимальном тексте на ширине 320 px. Горизонтального переполнения и обрезанных элементов в этих сценариях не обнаружено. Проверка выполнена в браузерных профилях, не на физических устройствах.
